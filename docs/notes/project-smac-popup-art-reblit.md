Screenshot audit 2026-09-20 (scratch detectors: two-colour run-length, lag-g vs lag-P row-luminance autocorrelation, lag-11 small window at 1920) found live banding on: in-game popup pictures (`*_sm.pcx`, 86 files carry a 1-row scanline dither), the version-popup logo, the faction-picker portrait, the diplomacy console base picture, the BIOSCAN figure backdrop + news thumbnail (flics). Measured row-luminance runs 2,1,2,1,2,2 @1600 and 1,1,2,1,2 @1920.

**Root cause (popups):** `0x940824` (= `g_faction_quote_popup` 0x9403E0 + 0x444) is the canvas of the SHARED BasePop object, not a faction-screen-only buffer. Every gate written as "dest==0x940824 -> faction portrait" also catches every in-game popup: `thunk_portrait_avg` (A5 bilinear) resampled all popup art, and `thunk_sd_reblit_wrap` skipped the council parity re-blit for it.

**Fix (group popup_art_reblit, src `assemble_artreblit.py`, laws `scaling_laws.art_reblit_row/col/art_reblit/quote_art_origin`, parity `tests\test_artreblit_asm_parity.py`, pcave2 0x29C00..0x29FF0):** `thunk_art_reblit` = edge-pinned parity re-blit — rows the edge-clamped centre map sends to source row 0 / sh-1 stay (1-px art frame keeps its NN share), interior rows = pair-granular parity held in [1, sh-2]. The council `thunk_parity_reblit` misplaces the bottom frame row on even-height art (frame one row early + a picture row under it), and its den/num centre map never reaches the last source row at small ratios (g=17, sh=10). Key arg > 0xFF = opaque. Entry points: `thunk_art_wrap` (thunk_sprite_draw's internal CALL; re-derives thunk_portrait_drop's x=fl(5g/16), y+fl(12(g-16)/16) because portrait_drop edits its own arg copy), `thunk_art_draw` (t_dp_sd2_hqpic tail), `thunk_art_flic` (wraps t_dp_flicdraw at the 3 Flic_draw_frame sites; re-blits from the native scratch Buffer via the Sprite-shaped `g_art_spr`).

**Correction 2026-09-20 (user's 1600 drone-riot shot on 7e9e2768 still measured 2,1,2,1,2,2):** BasePop_on_redraw has TWO art paths -- `call [popup+0x3168]` (Popup-class: Quit, faction quote) and the DIRECT `call Sprite_draw_2` @0x604C72 when that fn-ptr is 0 (the in-game event-picture modals). Only the first was covered; site `BasePop_on_redraw.art_draw_direct` -> `thunk_art_draw` (ratio-neutral drop-in) added in exe 050459e5. The '0x940824 is shared' claim above is UNPROVEN for in-game popups (thunk_pf_textfollow treats esi==0x9403E0 as faction-only); the wrap is still correct for whatever draws there.

**Correction 2 (2026-09-20, user's pixel-exact shots of 3e4fa0cf):** faction-picker + Datalinks portraits measured FIXED (all-1 runs); the drone-riot picture and version logo were UNCHANGED, because in-game popup pictures are FILENAME-BACKED sprites (pcBits NULL forever -- already recorded in [[reference-smac-sprite-struct-fields]], which I had not read) so every Sprite-level re-blit bails. Their pixels exist only as the canvas-manager src Buffer at the blit core's Buffer_draw_2 call @0x5E4C01 -> `thunk_art_core` (pcave2 0x1CAB0: calls thunk_flag_restripe, skips the UN flag by its content gate, re-blits via g_art_spr) in exe 84db4adf. LESSON: read the struct reference memory before writing a sprite consumer; a silent bail-out guard hides a no-op fix -- measure the screenshot, do not trust the build.

Mechanism: dip_?_n.flc runs KEYED (flags 0x3, key 9); Flic_init captures the flic's bg canvas (+4) as w x h NATIVE texels from the DEVICE-scaled strip (dst = MainWin strip buffer 0x7AEC64, not DiploTalkWin+0x444); the engine BG-restores that device-density patch into our native scratch every frame and substitutes it for key texels; then our x g/16 StretchBlt + parity re-blit mangle it.
