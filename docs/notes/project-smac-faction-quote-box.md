Faction-selection advisor quote box (portrait + leader quote), popup `g_faction_quote_popup` @0x9403E0,
winbuf **0x940824** (= `[popup+0xa3c]+0x444`; a clean faction-only identity gate).
**CLOSED 2026-07-09, build `75cae700` = VERIFIED RELEASE LOCK** (user "perfect at all resolutions",
4K + 1920×1080 + 1600×1200; CHANGELOG'd). Frame geometry, portrait anchor, uniform strokes, and the
quote overflow are all fixed. Thunk bytes are generated by `work\scripts\assemble_faction_frame.py`.

**Frame:** rects are pure `native × g/16`. `thunk_channel_adjust` sets the INNER d528;
`thunk_d5a0_center` sets OUTER d5a0 = inner grown by `ps3=(3g)>>4` on all sides → uniform `ps3` channel
by construction. `thunk_portrait_drop` anchors the portrait to the OUTER stroke (Y += `12*(g−16)/16`,
X := `5*g/16`). Strokes render at uniform integer thickness via `thunk_frame_intK` (`K=(g+7)>>4`, exact
`K:1` enlarge) — this kills the fractional `StretchBlt` 2-vs-3px phase, but is **faction-scoped**
(reached only via `d5a0_center`'s `g_faction_quote==1` branch + `thunk_dfstep1_dispatch`'s
`ecx==0x940824`). Globalizing it is a tracked OPEN item in the maintainer's work log.

**The two laws (both DERIVED from `thunk_faction_textmargin`'s own bytes @0xA0C6C0, never fitted):**
with `ps4 = g>>2`, `ps3 = (3g)>>4`, that thunk applies to the text draw:
`X += ps4 + 2*ps3 − 9` ; `Y += g − ps4 + 2*ps3 − 18` ; `width −= 4*ps3 − 12`.
(terranx.h's old note `X += 2*ps4+ps3−6, Y += g+ps3−18, width −= 2*ps4+2*ps3−12` was WRONG on all three.)
1. **`D = 4*ps3 − 12`** (16@g40, 4@g25, 4@g22, **0@g16**) — `thunk_faction_wrapwidth` (pcave2 0x6E00)
   subtracts the SAME `D` from the MEASURE's wrap budget at both `Buffer_wrap_height_flying` call sites
   (0x603e42 / 0x603f3d). Without it the draw wraps narrower than the measure → an extra rendered line →
   overflow (Yang, 4K only). See [[feedback-wrap-width-desync-line-step]].
2. **`K = g − ps4 + 2*ps3 − 18`** = that thunk's Y offset = `y_in − content_top` (26@g40, 9@g25, 7@g22,
   **0@g16**). `thunk_channel_adjust` sets `inner.B = content_top + content_h + ps3 + K`, emitted as
   `measB − d + 2*ps3 + g − 18` (`d = ps4−ps3`). v11's `K=(9g−152)>>3` was a 2-point fit through g=40/25
   → 5 (not 7) at 1920×1080. Both laws are 0 at g=16 → native byte-identical without a guard.

**Why the laws hold at EVERY g, not just the 3 tested res (proved, not sampled):**
- `W_meas == W_or` is an ALGEBRAIC identity, `g` doesn't appear: `BasePop_calculate_dimensions` ends with
  `box_width += [30f4]+[30f0]` (engine, @0x604262, unconditional), and `on_redraw`'s width subtracts
  exactly `[30f4]+[30f0]` more than the measure's `ebx`. They cancel — so the measure already wraps at
  the draw's pre-narrowing width, and textmargin's own subtraction is the ONLY delta.
- `D`/`K` are INSTRUCTION-LEVEL identities (same `sar`/`lea`/`shl` sequence ⇒ same floor rounding).
  Swept over the whole clamp g∈[16,40]: 0 mismatches; `D>=0` always (negative `D` would widen the
  measure into an under-count); `D==0` for g<=21 (ps3 still vanilla 3).
- `H_draw == content_h` pinned by INVARIANCE: `delta = K + (H_draw − content_h)`; a per-line height error
  would scale with line count, yet `delta` is identical across 6/7/8/9-line quotes at each res.
- The `ps3` STAIRCASE is why fitting fails: `D` steps 0→4→8→12→16 at g=22/27/32/38, `K` steps with it.
  A smooth fit interpolates over the treads. See [[feedback-wrap-width-desync-line-step]].

**Dead ends (do not retry):**
- **Capturing the drawn text bottom and feeding it forward is unsound.** The frame draws BEFORE the text
  in `BasePop_on_redraw`, and consecutive redraws carry different-length quotes, so the fed value is
  always the previous quote's → alternating over/underflow, never settles (v9/v10;
  `thunk_fac_bottom_stash` is now dead cave content, its site `status: skip`).
  Source the bottom from `BasePop_calculate_dimensions`' FRESH per-redraw measure instead.
- `g_popup_body_bottom` (0x9B8CE8) is SHARED — clobbered by other windows' `write_strings`. Reading it as
  the quote's bottom yields nonsense (`content_h=300 → "410"` was the faction LIST's bottom).
- Widening the DRAW width to match the measure → text overlaps the right border. The draw is the faithful
  side; fix the measure.
