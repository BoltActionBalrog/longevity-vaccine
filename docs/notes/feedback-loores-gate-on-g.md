---
name: feedback-loores-gate-on-g
description: a lo-res native no-op gate must key on g_popup_scale_num<=16, never on a ScreenWidth literal (1024=0x400 slips a <=0x3FF gate)
type: feedback
---

A thunk's lo-res "g≤16 → native no-op" gate MUST be written as `mov eax,[g_popup_scale_num]; cmp eax,16; jle native`, NOT as a ScreenWidth comparison.

**Why:** `thunk_d528_inset` (faction quote frame) gated on `cmp [ScreenWidth 0x9b7b1c], 0x3FF; jle END` — intending "≤1023 → no-op". But the native baseline is exactly 1024×768 and **1024 = 0x400 > 0x3FF**, so the gate MISSED at the native resolution and the thunk fired at g16 (extra=popup_scale(4)−3=1 → frame left+=4, bottom+=5 over text that stayed native) → the d528 frame overlapped the quote text at 1024×768. Every sibling faction thunk (textmargin, portrait_drop, channel_adjust, d5a0_center) correctly gates on g_popup_scale_num. Fixed b829a189 by re-gating on g.

**Second instance (2026-07-02):** `thunk_scale_boxw` v1 had the same `0x3FF` gate AND its non-list branch multiplied by the resolution-independent constant `g_boxw_num/16 = ×1.875` — so at 1024×768 every non-list popup (faction confirm, Planetfall, Quit) stretched to ~1170px on a 1024px screen. Fixed in v2 (build fdb27d65): g-gate + the multiplier interpolated `16+(g_boxw_num−16)(g−16)/24` so it's g-derived. KEY COROLLARY: a slipped gate is only *visibly* harmless when the scale path is pure `g/16` (identity at g=16); any thunk that multiplies by a **tuned constant** turns a gate slip into a gross blowout. When auditing `0x3FF` gates, triage by whether the math is g-derived — the remaining four (`thunk_wrap_budget` [dead site], `thunk_list_fill_width`, `thunk_pf_union_align`, `thunk_rowgap`) were audited 2026-07-02 and are pure g/16 → benign, left as-is.

**Third instance (2026-07-11):** `thunk_rowgap` v1 (fixed in v2, build 02dacea4: g-gate + scale only the measured native [+0x44]=3, law `scaling_laws.dialog_row_margin`). Here the 2026-07-02 "pure g/16 → benign" triage happened to be arithmetically TRUE (every dialog family's native margin is the struct-copy default 3, so the g=16 stomp of 3 was an identity — proven by the pixel-identical A/B builds at 1024), but the W-gate was still the law violation and was still replaced. The 1024×768 PrefWin +2px row pitch that exposed it was a DIFFERENT ungated patch on the same path: `popup_list_rowheight`'s direct Buffer_text_height→Buffer_text_line_height redirects added the font LEADING at g=16 (now routed through the gated thunk_quit_rowpitch helper). TWO COROLLARIES: (a) a g=16-identity audit of a shared path must check every patch ON the path per caller family — the rowheight redirect was even documented as ungated in its gated type-16 twin's comment and never made the audit list; (b) when a suspected fix lands and the pixels DON'T move, the root-cause was wrong — the A/B build diff is the cheapest ground truth, and no inferred (unmeasured) native value may enter a value map on its strength.

**How to apply:** When writing or auditing any scaling thunk's lo-res gate, use `g_popup_scale_num<=16`. If you ever must use a ScreenWidth literal, remember 1024 (=0x400) is the native g16 anchor and must be INCLUDED in the no-op (use `<=0x400`/`jle 0x400`, not `<=0x3FF`). This is the project invariant ([[feedback-smac-all-resolutions]], [[project-smac-scaling-baseline-1024]]): levers derive from the runtime screen scale g, gated `g≤16 → native no-op`. Same gating pattern reviewers: a g16/1024×768 run should be byte-identical to pristine behavior. Equal-length byte swap note: keep the jle as the LAST instruction of the gate region and pad with NOPs BEFORE it so the jump's disp offset to END is preserved.
