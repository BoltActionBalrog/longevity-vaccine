---
name: feedback-fragment-refresh-reverts-foreign-entries
description: Refreshing patches.yaml from a bake's regenerated fragments silently REVERTS any entry a later bake took over (thunk_btn_gate_pre se->rw, boot crash 2026-09-17); audit fragment offsets vs the yaml first, never --allow-relocate blindly
type: feedback
---

A fragment refresh (`refresh_rw_yaml.py` / `refresh_mon_yaml.py` / `refresh_fragments_yaml.py <prefix>`) replaces symbols, cave contents and site new_bytes BY ID from a bake's freshly regenerated fragments. If a LATER bake relocated or re-versioned one of those ids (rw_scale_shared moved `thunk_btn_gate_pre` v4 @0x16DA0 -> v5 @0x24230 and every rw/kinds/hof caller resolves it by `{rel32:}`), the older bake's fragment still carries the stale entry and the refresh puts it back: the symbol pointed at 0x16DA0, the v4 body was written there, the v5 callers landed in a thunk with a different contract -> AV at 0x498CA2 during the HUD I-button draw at 1600x1200 (dump terranx_PRACX.exe.43724.dmp). The suite stayed GREEN (parity tests emulate each script's own layout; integrity checks structure only), so tests do not catch this class.

**Why:** fragments are per-bake snapshots; ownership of a shared thunk moves between bakes over time, and nothing in the fragment says "no longer mine".
**How to apply:** (1) `refresh_fragments_yaml.py` now ABORTS when a fragment changes an entry's OFFSET (symbol or content) unless `--allow-relocate` is passed -- only pass it after checking the yaml comment / git log for who owns the entry. (2) A bake that hands an entry to a later bake must stop emitting it: `assemble_se.OWNED_ELSEWHERE` (still assembled for its parity tests, never written to the fragments); do the same in any assembler whose thunk gets relocated by a later bake. (3) Before ANY fragment refresh, diff the fragment's symbols/contents/sites against the committed yaml (`git show HEAD:work/patches/patches.yaml`) and explain every difference; the only legitimate ones are the bytes you changed. (4) A boot crash right after a refresh that "only changed data" is this class until proven otherwise: read the dump (Eip + the stack's cave addresses) before theorising.
