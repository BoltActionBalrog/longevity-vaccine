Crash 2026-10-03 on the RAW vanilla `terranx.exe` (MD5 cc659f, no mod DLL; DDrawCompat ddraw.dll + soundx.dll loaded): AV 0x5ACE7A in `compute_score` (0x5ACBE0) indexing Bases[] with SecretProjects[19] = 0xAE00D8. Dump `%LOCALAPPDATA%\CrashDumps\terranx.exe.20436.dmp`. This is the already-known Win11 24H2 save bug ([[project-smac-win11-24h2-fix]]), not a new bug — I first reported it as new and as "masked by luck" on the patched exe; an independent audit corrected both.

**Mechanism (audited: dump, save file and exe bytes agree on all 917 copied bytes):** `game_data` (0x5A6AC0, cdecl(FILE*, write)) never initialises its 0x374-byte local. On WRITE it fwrites 0x31C bytes of it as the header, then runs `cmp [ebp-0x70], 0xB; jge` (header SaveFileVersion, block +0x304) in write mode too. If < 11 it copies the junk over GamePreferences 0x9A6490, SecretProjects[0..32] (0x9A6514), -1 over [33..63], council/climate fields and the version global 0x9A6810 (so the rest of the save is emitted in legacy layout, ~41 KB short).
- Unfixed exe on 24H2: the slot holds 0, a local of an ntdll helper under `RtlLeaveCriticalSection`'s slow path, reached via CRT `_unlock_file` (0x647C89) in the preceding fwrite. Why the slow path is taken on build 26200 is NOT established.
- With `win11_24h2_filelock_fix` (fwrite/fread lock calls 0x646046/0x646061/0x64617F/0x64619A -> spinlock 0x668490/0x6684B0) no ntdll frame lands there; the slot keeps `HeapAlloc(_crtheap, 0, 0x1000)`'s heap-handle argument (0x2D10000..0x3BC0000 in 23 saves) — always >= 11. Systematic, but it rests on a stack-layout coincidence checked only for the `save_daemon` caller (0x5A967C).

**State 2026-10-04:** hardening group `save_header_init` (site 0x5A6AEB -> `thunk_save_header_init`, menu_strip_thunks 0x2D0: header zeroed, version 12) is LIVE in terranx_PRACX.exe and user-verified by a measured save. The game folder's `terranx.exe` (Pristine shortcut) is now **47b516ac** = raw cc659f + ONLY `win11_24h2_filelock_fix` + `save_header_init` (user request: "just enough for me to not crash"; no uimod loader, no credits fix, so it still loads no mod DLL); raw originals remain in `terranx.exe.bak` / `terranx_vanilla.exe.bak`. Re-create with `apply_patches.py --target <game>\terranx.exe --target-id vanilla --groups win11_24h2_filelock_fix,save_header_init --apply`. The maintainer's rule: vanilla-exe fixes are a dev convenience, NOT part of the release (the installer already skips non-launch targets).

**How to apply:** a crash or "garbage mission year / Set Password / units not placing" after a save, with 33 junk ints then -1s at 0x9A6514, on an exe WITHOUT the filelock group and without `save_header_init` = this (a raw cc659f `terranx.exe` on Windows 11 24H2 does it on its saves, including the scenario editor's undo saves). Check SecretProjects for 33 junk ints followed by -1s before bisecting patches. Saves with version field 0: the crash save (rotated to `saves\auto\... Autosave 5.SAV`) and `<game root>\Alpha Centauri Autosave 1.SAV` from 2026-07-04 — both likely unloadable.
